# Restricted agent tool boundary (downstream 0007)

Authenticated `POST /control/agents/{agent_id}/restricted/create` (under `/api`) requires a valid `tool_allowlist`. The ordinary create route rejects this field.

```json
{"tool_allowlist":{"tool_name_prefix":"fixture_","tools":[{"name":"fixture_record_lookup","description":"Look up a synthetic record","parameters":{"type":"object","properties":{"id":{"type":"string"}},"required":["id"],"additionalProperties":false}}],"bridge":{"url":"http://127.0.0.1:34567/call","bearer":"synthetic-ephemeral-example"}}}
```

Only explicitly registered tools are enabled. `tool_name_prefix` is required, begins with a lowercase ASCII letter, ends with `_`, and contains 2–63 lowercase ASCII letters, digits, or underscores. Each name must begin with that prefix and add a nonempty suffix, with 8–64 characters total. No native tool is enabled by this field, including shell/batch, filesystem, Work, Memory, timers, web, delegation, Sleep, and report settlement. Unknown policy fields, duplicate wire fields, explicit null, malformed values, duplicate/colliding names, unsupported schemas and nonliteral/nonloopback URLs fail closed. The restricted schema subset supports type, properties, required, additionalProperties (boolean), items, enum, const/default, title/description, numeric bounds, and length/item bounds; schema recursion is bounded. At most 16 tools and 64 KiB policy/request/reply; descriptions at most 4096 bytes. Bearer is 16–256 ASCII token characters. Only HTTP literal `127.0.0.1` or `[::1]` with explicit nondefault port and `/call` is accepted.

Identity's `tool_allowlist_required` marker, private per-incarnation settings and bootstrap commit in one transaction. Settings are not projected in bootstrap or agent views. Existing incarnation create requests are rejected; there is no policy update API. Missing/malformed required settings reject catalog and dispatch, including after restart. Schema migration 108 prevents rollback to binaries supporting only 107. Restricted creation makes the DB and existing WAL/SHM owner-only on Unix; verified backups are created owner-only before copying. Private settings are purged on fenced deletion and excluded from logical agent history export. Treat the runtime DB and physical backups as credential-bearing private data. This is an in-process agent/tool boundary, not OS sandboxing: unrestricted legacy actors and other processes running as the daemon UID remain trusted and can read that UID's private storage. Isolate the restricted runtime identity/storage from untrusted shell-enabled actors; changing legacy actors' OS execution is outside this patch. Non-UTF-8 backup destinations fail closed rather than writing to a lossy path.

Create returns top-level `tool_allowlist_applied:true` only after readback of the exact policy on the returned incarnation. Ordinary create omits this field. Drivers must require this marker; a historical generic receipt is insufficient.

Authenticated `GET /control/runtime/restricted-agent-capabilities` (under the normal `/api` mount) returns `{"toolAllowlist":true,"promptCancellation":true}`. This downstream patch is delivered atomically with the cancellation worker's companion prompt cancellation routes; the capability advertises that combined artifact and must not be shipped standalone.

Each tool calls the Service bridge directly via POST `{name,args}` with bearer authentication, no shell or generic executor. Redirects and proxies are disabled; connect/overall timeouts are 2/10 seconds. A successful response is `{ok:true,result:...}`. Other responses, transport failures, oversized IO, or credential echo (including JSON escapes) produce a bounded generic tool error without URL/body/credential. The Service owns the registered tool implementation and validates business arguments/action gates; the runtime forwards only the registered name and arguments.

Provider catalog paths cover ordinary/bootstrap turns, captured/projection contexts and host-side previews. A final request gate strips forbidden function tools and native web search before provider execution. Tool batches are prechecked before special processing, with separate checks at registry, native dispatcher, and deferred WaitFor/CompleteWorkItem settlement. Provider-native search is disabled; OpenAI custom tool parsing maps to the same ToolUse dispatch and Anthropic server tools require native search request configuration. Image adapter and subagent one-shot requests advertise no tools and do not dispatch returned calls.
